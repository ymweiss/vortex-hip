# HIP to Vortex: End-to-End Integration Plan

This document describes how HIP source code flows through the compilation pipeline to produce executables that run on Vortex.

## Key Insight

**Vortex already has complete infrastructure for running host+device binaries.** The existing test framework (`vortex/tests/regression/`) demonstrates:

```makefile
# From vortex/tests/regression/common.mk
all: $(PROJECT) kernel.vxbin kernel.dump

run-simx: $(PROJECT) kernel.vxbin
	VORTEX_DRIVER=simx ./$(PROJECT) $(OPTS)

run-rtlsim: $(PROJECT) kernel.vxbin
	VORTEX_DRIVER=rtlsim ./$(PROJECT) $(OPTS)
```

**Our goal**: Produce the same artifacts from HIP source:
- `kernel.vxbin` - Device binary (RV32 + Vortex extensions)
- Host executable linked with `-lvortex`

Once we have these, we use the existing Vortex execution infrastructure unchanged.

## Execution Flow

### 1. Host Program Startup

The host program links against `libhip_vortex` and `libvortex`:

```cpp
#include "vortex_hip_runtime.h"

int main() {
    hipInit(0);           // → vx_dev_open()
    hipSetDevice(0);      // → stores device handle
    // ...
}
```

### 2. Memory Allocation

```cpp
float *d_ptr;
hipMalloc(&d_ptr, size);  // → vx_mem_alloc() + store handle as ptr
```

**Implementation** (`runtime/hip_vortex_runtime/src/hip_memory.cpp`):
- `vx_mem_alloc()` returns opaque `vx_buffer_h`
- Handle is stored as the `void*` returned to user
- `vx_mem_address()` gets actual device address when needed

### 3. Memory Transfer

```cpp
hipMemcpy(d_ptr, h_ptr, size, hipMemcpyHostToDevice);
// → vx_copy_to_dev((vx_buffer_h)d_ptr, h_ptr, 0, size)
```

### 4. Kernel Launch

```cpp
hipLaunchKernelGGL(vecadd, grid, block, 0, 0, d_a, d_b, d_c, N);
```

**Implementation** (`runtime/hip_vortex_runtime/src/hip_kernel.cpp`):

1. Look up kernel in registry (or load from `VORTEX_KERNEL_PATH`)
2. Pack arguments into struct:
   ```cpp
   struct KernelArgs {
       uint32_t grid_dim[3];
       uint32_t block_dim[3];
       // User arguments follow (device addresses)
   };
   ```
3. Upload argument struct: `vx_upload_bytes()`
4. Launch: `vx_start(device, kernel_buffer, args_buffer)`

### 5. Synchronization

```cpp
hipDeviceSynchronize();   // → vx_ready_wait(device, VX_MAX_TIMEOUT)
```

### 6. Result Retrieval

```cpp
hipMemcpy(h_ptr, d_ptr, size, hipMemcpyDeviceToHost);
// → vx_copy_from_dev(h_ptr, (vx_buffer_h)d_ptr, 0, size)
```

## Device Kernel Structure

### Generated Kernel Binary

The device binary contains:

1. **Startup code** (`vx_start.S` from libvortex.a)
2. **Kernel main()** - reads args from CSR, calls `vx_spawn_threads()`
3. **Kernel body** - user's `__global__` function (lowered)

### Kernel Entry Point Pattern

```cpp
// Generated by lowering pipeline
#include <vx_spawn.h>
#include <vx_intrinsics.h>

typedef struct {
    uint32_t grid_dim[3];
    uint32_t block_dim[3];
    uint64_t arg0;  // d_a device address
    uint64_t arg1;  // d_b device address
    uint64_t arg2;  // d_c device address
    uint32_t arg3;  // N
} kernel_args_t;

// User's kernel (lowered from __global__ function)
void vecadd_body(kernel_args_t* args) {
    float* a = (float*)args->arg0;
    float* b = (float*)args->arg1;
    float* c = (float*)args->arg2;

    // threadIdx/blockIdx accessed via vx_get_* functions
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < args->arg3) {
        c[idx] = a[idx] + b[idx];
    }
}

int main() {
    kernel_args_t* args = (kernel_args_t*)csr_read(VX_CSR_MSCRATCH);

    // Initialize grid/block dimensions from args
    gridDim = (dim3_t){args->grid_dim[0], args->grid_dim[1], args->grid_dim[2]};
    blockDim = (dim3_t){args->block_dim[0], args->block_dim[1], args->block_dim[2]};

    return vx_spawn_threads(3, args->grid_dim, args->block_dim,
                           (vx_kernel_func_cb)vecadd_body, args);
}
```

## Complete Compilation Commands

### Step 1: Split HIP Source

```bash
python3 scripts/hip_splitter.py vecadd.hip -o build/
# Outputs:
#   build/vecadd_kernel.hip   (device code)
#   build/vecadd_host.cpp     (host code)
#   build/build_vecadd.sh     (build script)
```

### Step 2: Compile Device Code

```bash
# HIP → GPU MLIR
scripts/polygeist/hip-to-gpu-dialect.sh build/vecadd_kernel.hip

# GPU MLIR → Vortex MLIR (generates metadata)
Polygeist/build/bin/polygeist-opt \
    --convert-gpu-to-vortex \
    build/vecadd_kernel.mlir \
    -o build/vecadd_kernel_vortex.mlir

# Lower to LLVM
Polygeist/build/bin/polygeist-opt \
    --gpu-to-llvm \
    --convert-func-to-llvm \
    --reconcile-unrealized-casts \
    build/vecadd_kernel_vortex.mlir \
    | Polygeist/build/bin/mlir-translate --mlir-to-llvmir \
    -o build/vecadd_kernel.ll

# Compile to RV32 object
$LLVM_VORTEX/bin/clang \
    -target riscv32-unknown-elf \
    -march=rv32imaf -mabi=ilp32f \
    -O3 -mcmodel=medany \
    -Xclang -target-feature -Xclang +vortex \
    -I$VORTEX_HOME/kernel/include \
    -c build/vecadd_kernel.ll -o build/vecadd_kernel.o

# Link with Vortex runtime
$LLVM_VORTEX/bin/clang \
    -target riscv32-unknown-elf \
    -nostartfiles -nostdlib \
    -Wl,-Bstatic,--gc-sections \
    -Wl,-T,$VORTEX_HOME/kernel/scripts/link32.ld \
    -Wl,--defsym=STARTUP_ADDR=0x80000000 \
    build/vecadd_kernel.o \
    $VORTEX_HOME/build/kernel/libvortex.a \
    -L$LIBC_VORTEX/lib -lm -lc \
    $LIBCRT_VORTEX/lib/baremetal/libclang_rt.builtins-riscv32.a \
    -o build/vecadd_kernel.elf

# Generate .vxbin
python3 $VORTEX_HOME/kernel/scripts/vxbin.py \
    build/vecadd_kernel.elf build/vecadd_kernel.vxbin
```

### Step 3: Compile Host Code

```bash
g++ -std=c++17 -O2 \
    -I runtime/hip_vortex_runtime/include \
    -I $VORTEX_HOME/runtime/include \
    build/vecadd_host.cpp \
    -L runtime/hip_vortex_runtime/lib -lhip_vortex \
    -L $VORTEX_HOME/build/runtime -lvortex \
    -lpthread \
    -o build/vecadd
```

### Step 4: Run

```bash
# Set kernel path
export VORTEX_KERNEL_PATH=build/

# Set library path
export LD_LIBRARY_PATH=$VORTEX_HOME/build/runtime:$LD_LIBRARY_PATH

# Run
./build/vecadd
```

## Host Library Compilation (Experimental)

The `--host-library` flag enables a new compilation mode that generates kernel launch code directly from MLIR, eliminating the need for Python-based source preprocessing.

### How It Works

1. **Device compilation** proceeds as normal, producing `kernel.vxbin`
2. **Host launch code** is generated from GPU MLIR using the `--convert-gpu-launch-to-host-call` pass
3. The launch code is compiled to an object file and linked with the host source

### Usage

```bash
./scripts/compile_hip_v2.sh input.hip --host-library -o output
```

This produces:
- `input_kernel.vxbin` - Device binary
- `output` - Host executable with embedded launch code

### Source File Structure

For host library compilation, the source file should use `#ifdef __CUDA__` guards:

```cpp
#ifdef __CUDA__
// Device compilation (cgeist)
#include "hip_runtime.h"

__global__ void kernel(float* a, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) a[idx] *= 2.0f;
}

void launch_kernel(float* d_a, int n, int block_size) {
    dim3 grid((n + block_size - 1) / block_size);
    dim3 block(block_size);
    hipLaunchKernelGGL(kernel, grid, block, 0, 0, d_a, n);
}

#else
// Host compilation (g++/clang++)
#include "hip_vortex_host.h"

// Declaration for MLIR-generated launch wrapper
void launch_kernel(float* d_a, int n, int block_size);
#endif

#ifndef __CUDA__
int main() {
    // Host-only code...
    launch_kernel(d_a, N, BLOCK_SIZE);
    // ...
}
#endif
```

### Generated Launch Object

The MLIR pass generates a launch function that:
1. Packs grid/block dimensions and kernel arguments
2. Converts host pointers to device addresses using `hip_ptr_to_device_addr()`
3. Calls `vortex_launch_with_args()` to execute the kernel

## Automatic Host/Device Code Separation

### Overview

The cgeist compiler handles host/device code separation internally, requiring **no `#ifdef __CUDA__` guards** in source files. This is achieved through:

1. **Device Stub Headers** - Intercept problematic STL headers during device compilation
2. **Host Function Stripping** - The `--strip-host-only-functions` pass removes host-only functions from device MLIR
3. **Dual Compilation** - The same source is compiled twice: once by cgeist for device, once by g++ for host

### Device Stub Headers

Located in `Polygeist/tools/cgeist/include/polygeist_device_stubs/`, these headers are added via `-I` in `compile_hip_v2.sh` with highest priority. They solve issues like GCC's `__float128` that Clang's CUDA frontend doesn't support.

**Stub headers provided:**
- `iostream` - Minimal ostream stubs, chains to real header for host
- `vector` - Empty for device mode, chains to real header for host
- `cstdlib` - Full declarations including `strtold` for `std::stold`
- `cstdio` - stdio declarations without printf (handled by `hip_runtime.h`)
- `cstring`, `string`, `fstream`, `sstream`, `cmath`, `stdio.h`, etc.

**How they work:**

Stubs use `#ifdef __CUDA__` (not `__CUDA_ARCH__`) because both host and device compilation jobs define `__CUDA__`, but need these stubs:

```cpp
// Example: polygeist_device_stubs/cstdlib
#ifdef __CUDA__
// CUDA compilation: provide declarations without __float128
extern "C" {
  int abs(int n);
  long labs(long n);
  long double strtold(const char* str, char** endptr);  // Required by std::stold
  // ... other functions
}
namespace std {
  using ::abs;
  using ::strtold;
  // ...
}
#else
// Non-CUDA compilation: use real header
#include_next <cstdlib>
#endif
```

**Implementation in compile_hip_v2.sh:**
```bash
DEVICE_STUBS_INCLUDE="$POLYGEIST_BUILD/include/polygeist_device_stubs"

run_cmd "$CGEIST" "$CGEIST_INPUT" \
    ...
    -I"$DEVICE_STUBS_INCLUDE" \  # Added first for highest priority
    -I"$HIP_DEVICE_INCLUDE" \
    ...
```

### printf Declaration Requirement

CUDA compilation parses ALL code for BOTH host and device jobs (with different `__CUDA_ARCH__` values). The printf declaration must work in both contexts:

```cpp
// hip_runtime.h - Works for both compilation contexts
extern "C" __host__ __device__ int printf(const char*, ...);
```

Using `#ifdef __CUDA_ARCH__` for conditional declarations fails because the host job parses kernel code but only sees the host printf (lacking `__device__`).

### Host Function Stripping

The `--strip-host-only-functions` pass in `polygeist-opt` removes functions marked with the `polygeist.host_only_func` attribute from device MLIR. This allows host code (like `main()`) to be parsed and type-checked, then filtered out before device code generation.

**Usage:**
```bash
polygeist-opt input.mlir --convert-gpu-to-vortex --strip-host-only-functions -o device.mlir
```

### Advantages of Internal Splitting

1. **Zero source modification** - Standard HIP code works unmodified
2. **Type safety** - Host code is fully type-checked even during device pass
3. **Single file** - No need to split into separate host/device files
4. **Portable** - Same code compiles on real HIP/CUDA platforms

### Expected Debug Output

When compiling code that uses `std::vector` or other complex STL types, cgeist will emit debug messages:
```
cleanup of materialized not handledCXXConstructExpr ...
cleanup not handled
warning: assuming __builtin_is_constant_evaluated to be false
warning: ignoring __builtin_expect
```

These are expected Polygeist behavior for C++ constructs it can't fully handle, and do not prevent successful compilation.

### Source File Requirements

Write standard HIP code without special guards:

```cpp
#include <hip/hip_runtime.h>
#include <iostream>
#include <vector>
#include <cstdlib>

__global__ void vecadd(const float* a, const float* b, float* c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) c[i] = a[i] + b[i];
}

int main() {
    std::vector<float> h_a(N), h_b(N), h_c(N);
    float *d_a, *d_b, *d_c;

    hipMalloc(&d_a, N * sizeof(float));
    hipMalloc(&d_b, N * sizeof(float));
    hipMalloc(&d_c, N * sizeof(float));

    // ... initialize h_a, h_b ...

    hipMemcpy(d_a, h_a.data(), N * sizeof(float), hipMemcpyHostToDevice);
    hipMemcpy(d_b, h_b.data(), N * sizeof(float), hipMemcpyHostToDevice);

    hipLaunchKernelGGL(vecadd, dim3((N+255)/256), dim3(256), 0, 0,
                       d_a, d_b, d_c, N);
    hipDeviceSynchronize();

    hipMemcpy(h_c.data(), d_c, N * sizeof(float), hipMemcpyDeviceToHost);

    // ... verify results using std::cout ...

    hipFree(d_a);
    hipFree(d_b);
    hipFree(d_c);
    return 0;
}
```

## Execution (Using Existing Vortex Infrastructure)

Once binaries are compiled, execution uses standard Vortex commands:

```bash
# SimX (fast software simulation)
VORTEX_DRIVER=simx ./vecadd

# RTL simulation (cycle-accurate)
VORTEX_DRIVER=rtlsim ./vecadd

# FPGA (Intel OPAE)
VORTEX_DRIVER=opae ./vecadd

# FPGA (Xilinx XRT)
VORTEX_DRIVER=xrt ./vecadd
```

The host binary automatically:
1. Loads `kernel.vxbin` via `vx_upload_kernel_file()`
2. Executes on the selected backend (simx/rtlsim/fpga)
3. Returns results

**No changes needed to Vortex runtime or simulators.**

### Feature-Specific Notes

- **`__shared__` + `__syncthreads()`**: Requires shared memory lowering in GPUToVortex pass
- **2D indexing**: Requires proper `threadIdx.x`/`threadIdx.y` handling
- **Multiple kernels**: Each kernel gets separate `.vxbin`, host switches between them
- **Device printf**: Requires printf buffer setup in runtime
